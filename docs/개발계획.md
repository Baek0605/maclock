# MacLock 개발 계획

원칙: **처음부터 끝까지 한 번 동작하게 만든 뒤, 하나씩 좋게 바꾼다.**
막히면 기능을 늘리기보다 동작하는 상태를 유지한다.

## 일정

| 주차 | 단계 | 주말까지 손에 남는 것 |
|---|---|---|
| 1주 | 0~5단계 | 키워드 검색 + AI 답변 + 화면이 처음부터 끝까지 동작 |
| 2주 | 6~7단계 | 임베딩 검색 + 질문 20개 채점 결과 |
| 3주 | 8단계 + 발표 | 배포된 링크 + 외부 사용자 테스트 + 발표 |

## 역할

| 역할 | 맡는 일 | 담당 |
|---|---|---|
| 수집·저장 | GitHub API, 기록 정리, 마스킹, Supabase | |
| 검색·AI | 키워드/임베딩 검색, 답변 지시문, 채점 | |
| 화면·배포 | Next.js 화면, Vercel, 사용량 제한 | |

## 0단계. 준비 (1주 차 첫날)

- [ ] GitHub 저장소 만들고 팀원 초대
- [ ] `.env.local` 만들기 (`.env.example` 참고). `git status`에 안 보이는지 확인
- [ ] GitHub 토큰 발급 (Fine-grained, 공개 저장소 읽기만)
- [ ] 테스트 저장소 만들기: 개인 프로젝트 `error-lab`을 **Public** 저장소로 올리고, 버그 5개를 이슈로 등록 → 고치는 PR로 닫기. PR 설명에 원인과 고친 이유를 적는다.

**확인:** `npm run dev`로 화면이 뜨고, 테스트 저장소에 이슈와 PR이 쌓여 있다.

## 1단계. GitHub에서 기록 가져오기 (수집·저장)

`app/api/import/route.ts`
- 저장소 주소에서 `owner/repo`를 뽑는다.
- 커밋 `GET /repos/{owner}/{repo}/commits`, PR `GET /repos/{owner}/{repo}/pulls?state=all`, 이슈 `GET /repos/{owner}/{repo}/issues?state=all` (이슈 목록에 섞인 PR은 걸러낸다)
- 요청 헤더에 `GITHUB_TOKEN`을 넣는다. 없으면 요청 한도가 금방 찬다.
- 최근 500개까지만 가져온다.

**확인:** 테스트 저장소 주소를 넣으면 커밋·PR·이슈 목록이 JSON으로 나온다.

## 2단계. 기록 정리하기 (수집·저장)

```ts
type Record = {
  id: string;          // "pr-12", "issue-9", "commit-a1b2c3"
  type: "commit" | "pr" | "issue";
  title: string;
  body: string;        // 너무 길면 앞부분만 (예: 2,000자)
  date: string;
  url: string;         // 원본 링크. 근거로 보여 준다
};
```
- 마스킹: 개인 프로젝트 `masking.py` 규칙을 `lib/masking.ts`로 옮긴다. (Bearer 토큰, `sk-` 키, 접속 주소 비밀번호, `password=`·`token=`, 이메일)
- 1주 차에는 로컬 JSON 파일로 저장한다. (Vercel 배포 후에는 파일 저장이 유지되지 않으므로 6단계에서 Supabase로 바꾼다)

**확인:** 기록이 `Record` 모양으로 저장되고, 일부러 넣은 가짜 토큰이 가려져 있다.

## 3단계. 키워드 검색으로 먼저 완성하기 (검색·AI)

- 질문을 단어로 나누고, 제목·본문에 단어가 많이 들어간 기록 순서로 10개를 고른다.
- 아직 AI 검색을 쓰지 않는다. 끝까지 한 번 동작하게 만드는 게 목표다.

**확인:** "결제 에러"를 물으면 결제 관련 PR과 이슈가 위에 나온다.

## 4단계. AI로 답변 만들기 (검색·AI)

`app/api/ask/route.ts`
1. 찾은 기록 10개에 번호를 붙여 정리한다.
2. mini급 모델에 **지시문 + 기록 10개 + 질문**을 보낸다.
3. 지시문 핵심
   - 준 기록 안의 내용만 쓸 것
   - 모든 내용에 근거 기록 번호를 붙일 것
   - 관련 기록이 없으면 "관련 기록을 찾지 못했습니다"
   - 형식: 무슨 문제였나 / 왜 바꿨나 / 어떻게 고쳤나 / 근거
4. 근거 번호를 실제 링크로 바꾸는 건 **코드**가 한다. AI가 링크를 쓰게 하면 없는 링크를 만들 수 있다.
5. 답변 최대 길이(`max_tokens`)를 정해 둔다.

**확인:** 근거 링크가 붙은 답이 나오고, 상관없는 질문에는 "찾지 못했습니다"가 나온다.

## 5단계. 화면 만들기 (화면·배포, 1~4단계와 동시에)

- 처음에는 **가짜 응답**으로 개발한다. API를 부르지 않으니 비용이 들지 않는다.
- 화면: 저장소 연결 → 질문 입력 → 답변 + 근거 카드
- 로딩 표시, 에러 안내 문구

**확인 (1주 차 목표):** 키워드 검색 + AI 답변 + 화면이 연결돼 처음부터 끝까지 동작한다.

## 6단계. 임베딩 검색으로 바꾸기 (2주 차)

1. Supabase 프로젝트를 만들고 `vector` 확장을 켠다. 테이블에 기록 내용과 `embedding vector(1536)` 칸을 만든다.
2. 가져올 때 기록마다 `text-embedding-3-small`로 임베딩을 만들어 함께 저장한다. 이미 저장된 저장소는 다시 만들지 않는다.
3. 질문할 때 질문을 임베딩으로 바꾸고 가장 가까운 기록 10개를 찾는다.
4. 3단계 키워드 검색 대신 이걸 쓴다. 4단계 답변은 그대로다.

**확인:** "로그인 안 돼요"처럼 기록에 없는 단어로 물어도 관련 기록이 나온다.

## 7단계. 채점하고 고치기 (2주 차 후반)

`data/questions.json`에 질문 20개와 정답 기록을 정리한다. 관련 기록이 **없는** 질문도 몇 개 넣는다.

| 질문 | 정답 기록 | 정답 기록이 근거에 있나 | 지어낸 내용 없나 | 없을 때 "찾지 못함" |
|---|---|---|---|---|

틀린 질문은 원인을 나눈다.
- **검색이 못 찾음** → 가져오는 범위, 본문 자르는 길이, 찾는 개수 조정
- **찾았는데 답이 이상함** → 지시문 고치기

고칠 때마다 Decision Log에 남긴다.

**완료 조건 (팀 결정):** 질문 20개 중 15개 이상에서 정답 기록을 찾고, 관련 기록이 없는 질문에서는 하나도 지어내지 않으면 끝.

## 8단계. 배포와 안전장치 (3주 차)

1. GitHub 저장소를 Vercel에 연결한다.
2. OpenAI 키, GitHub 토큰, Supabase 주소와 키를 Vercel 환경 변수에 등록한다.
3. 같은 사용자(IP)가 1분에 몇 번 이상 질문하지 못하게 제한한다. 가져오는 기록 수도 제한한다.
4. 팀원이 아닌 사람에게 링크를 주고, **자기 공개 저장소**로 써 보게 한다. (AI:Shoot 5번 완료 조건)
5. 시연이 끝나면 배포를 내리거나 키를 비활성화한다.

**확인:** 다른 컴퓨터에서 링크를 열어 저장소를 넣고 질문했을 때 답이 나온다.

## 걱정되는 점과 대비

| 걱정 | 대비 |
|---|---|
| 검색·답변 구현이 어려움 | 1주 차는 키워드 검색으로 끝까지 동작하게. 임베딩이 막히면 키워드 검색 그대로 배포 |
| 커밋 메시지가 "fix"뿐인 저장소 | 테스트는 PR·이슈가 잘 쓰인 저장소로 |
| AI가 지어냄 | 근거 링크 필수, 기록 밖 내용 금지, "찾지 못함" 테스트 질문 |
| 큰 저장소는 오래 걸림 | 최근 기록 500개까지만 |
| 공개 링크 악용 | 질문 횟수 제한, 시연 후 배포 내리기 |

## 개인 프로젝트와 이어지는 점

- 개인 프로젝트(서버 오류 로그 분석)에서 팀 프로젝트와 겹쳐 뺐던 **"예전에 어떻게 고쳤나"**를 MacLock이 맡는다. 에러 로그를 질문으로 넣을 수 있게 한다.
- `error-lab` 테스트 서버를 정답 있는 테스트 저장소로 쓴다.
- 마스킹 규칙을 그대로 옮겨 쓴다.
- "근거를 붙이고, 판단은 사람이" 원칙: 근거 줄 번호 → 근거 커밋·PR 링크
