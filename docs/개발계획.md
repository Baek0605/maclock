# MacLock 개발 계획

원칙: **처음부터 끝까지 한 번 동작하게 만든 뒤, 하나씩 좋게 바꾼다.**
막히면 기능을 늘리기보다 동작하는 상태를 유지한다.

## 지금 상태 (11/21)

화면은 팀 시안(DevTrace AI 대시보드)을 Next.js로 옮겼고, 아래까지 동작한다.

- [x] 메뉴 5개: 대시보드, 통합 히스토리, AI 지식 검색, 오류 원인 분석, 자료 등록
- [x] GitHub 저장소 연결: 공개 저장소의 PR·이슈·커밋을 가져와 히스토리에 추가 (`/api/import`)
- [x] 문서 직접 등록, 텍스트 파일 불러오기
- [x] 민감정보 마스킹 (토큰, API 키, 비밀번호, 이메일, 전화번호)
- [x] 키워드 검색으로 관련 기록 찾기
- [x] AI 답변 (`/api/ask`): 찾은 기록만 넘기고, 답의 근거 id가 실제 기록인지 코드로 검증
- [x] 키가 없으면 가짜 답 없이 관련 기록만 표시
- [x] 같은 사용자 요청 횟수 제한
- [x] 가져온 기록은 브라우저에 저장 (새로고침해도 유지)

**검증한 것 (가짜 AI 서버와 예시 GitHub 응답으로 테스트)**
- AI가 없는 근거 id를 쓰면 버리고, 근거 없는 원인은 화면에 보이지 않는다.
- 직접 등록한 기록의 이메일·토큰은 AI에게 보내기 전에 가려진다.
- 관련 없는 질문에는 "관련 기록을 찾지 못했습니다"가 나온다.

**아직 확인 못 한 것**
- 실제 OpenAI 키로 답변 품질 (키 받으면 바로 확인)
- 실제 GitHub 저장소 가져오기 (토큰 넣고 테스트 저장소로 확인)

## 1. 키 넣고 실제로 확인하기 (지금 바로)

1. `.env.local`에 `GITHUB_TOKEN`, `OPENAI_API_KEY`를 넣고 `npm run dev`를 다시 켠다.
2. 화면 위쪽에 "AI 연결됨"이 뜨는지 본다.
3. 자료 등록 → 테스트 저장소 주소 → 가져오기
4. AI 지식 검색에서 질문해 보고, 근거의 "GitHub ↗"가 맞는 원문으로 가는지 본다.
5. OpenAI 에러가 "모델 이름"이라고 나오면 `.env.local`의 `OPENAI_MODEL`에 쓸 수 있는 모델 이름을 넣는다.

## 2. 테스트 저장소 만들기

MacLock이 맞게 찾는지 채점하려면 **정답을 아는 저장소**가 필요하다.

- 개인 프로젝트의 `error-lab`을 **Public** 저장소로 올린다.
- 버그 5개를 이슈로 등록하고, 하나씩 고치는 PR로 닫는다. PR 설명에 원인과 고친 이유를 쓰고 `Closes #이슈번호`를 넣는다.
- 기능 추가 커밋도 몇 개 섞어서 기록을 30~50개로 만든다.
- 우리 `maclock` 저장소도 PR 설명을 잘 쓰면 두 번째 테스트 저장소가 된다.

## 3. 질문 20개와 채점

`data/questions.json`에 질문 20개와 정답 기록 id를 정리한다. 관련 기록이 **없는** 질문도 몇 개 넣는다.

| 질문 | 정답 기록 | 정답이 근거에 있나 | 지어낸 내용 없나 | 없을 때 "찾지 못함" |
|---|---|---|---|---|

틀린 질문은 원인을 나눈다.
- **검색이 못 찾음** → 검색 방식, 가져오는 범위, 넘기는 기록 수 조정
- **찾았는데 답이 이상함** → `lib/prompt.ts` 지시문 고치기

고칠 때마다 Decision Log에 남긴다.

**완료 조건 (팀 결정):** 질문 20개 중 15개 이상에서 정답 기록을 찾고, 관련 기록이 없는 질문에서는 하나도 지어내지 않으면 끝.

## 4. 임베딩 검색으로 바꾸기 (2주 차)

키워드 검색은 "로그인 안 됨"과 "인증 실패"를 다른 말로 본다. 뜻으로 찾게 바꾼다.

1. Supabase 프로젝트를 만들고 `vector` 확장을 켠다. 기록 내용과 `embedding vector(1536)` 칸이 있는 테이블을 만든다.
2. 가져올 때 기록마다 `text-embedding-3-small`로 임베딩을 만들어 저장한다. 이미 저장된 저장소는 다시 만들지 않는다.
3. 질문할 때 질문을 임베딩으로 바꾸고 가장 가까운 기록을 찾는다.
4. `lib/search.ts`의 `findRelated`만 바꾸면 나머지는 그대로 동작한다.

**막히면:** 키워드 검색 그대로 배포해도 서비스는 동작한다.

## 5. 배포와 안전장치 (3주 차)

1. GitHub 저장소를 Vercel에 연결한다.
2. `OPENAI_API_KEY`, `OPENAI_MODEL`, `GITHUB_TOKEN`(+ Supabase)을 Vercel 환경 변수에 등록한다.
3. 팀원이 아닌 사람에게 링크를 주고, **자기 공개 저장소**로 써 보게 한다. (AI:Shoot 5번 완료 조건)
4. 시연이 끝나면 배포를 내리거나 키를 비활성화한다.

## 개인 프로젝트와 이어지는 점

- 개인 프로젝트(서버 오류 로그 분석)에서 팀 프로젝트와 겹쳐 뺐던 **"예전에 어떻게 고쳤나"**를 MacLock이 맡는다. 에러 메시지를 질문으로 넣어도 된다.
- `error-lab`을 정답 있는 테스트 저장소로 쓴다.
- 마스킹 규칙을 그대로 옮겨 썼다 (`lib/masking.ts`).
- "근거를 붙이고, 판단은 사람이" 원칙: 근거 줄 번호 → 근거 기록과 GitHub 링크
