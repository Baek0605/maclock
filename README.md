# MacLock

> 개발팀의 과거를 검색 가능한 지식으로.

GitHub 저장소를 연결하고 "예전에 이거 왜 바꿨지?"를 물으면, 관련 커밋·PR·이슈와 팀 문서를 찾아 **근거 링크와 함께** 답해 주는 서비스입니다.

**핵심 메시지:** 코드는 남지만, 맥락은 남지 않는다.

- 팀: 디버그 (AI:Shoot 팀 프로젝트, 웹 개발 직무)
- 유형: AI:Shoot A형 (화면 제작) — 화면, 실제 AI 연결, Vercel 배포
- 화면 디자인: 팀 시안 "DevTrace AI 대시보드"를 옮겨 왔습니다.

---

## 왜 만드나

코드는 남아 있지만, 왜 이렇게 바뀌었는지는 커밋·PR·이슈와 팀 문서, 과거 문의에 흩어져 있습니다. 그래서 이미 해결한 문제를 다시 조사하거나 담당자에게 반복해서 물어보게 됩니다.

**근거 (링커슈 현직자 인터뷰, 컨택 보고서 Ⅳ 핵심 병목 ①)**
> "신규 기능 개발 시 기존 시스템 코드의 이해 및 과거 작업 히스토리 파악에 많은 시간이 소요되는 문제"

멘토님은 과거 문의 답변과 오류 로그를 기반으로 히스토리를 정리하는 AI를 "기획을 생각했다"고 답하셨습니다.

## 화면 (메뉴 5개)

| 메뉴 | 하는 일 |
|---|---|
| 대시보드 | **문의·오류를 입력하면 AI 오류 분석 리포트로 바로 이동**, 기록 수, AI 연결 상태, 최근 기록 |
| 통합 히스토리 | 커밋·PR·이슈·팀 문서·CS 기록을 검색하고 팀/유형으로 거르기, 원문 보기 |
| AI 지식 검색 | 자연어 질문 → 관련 기록을 근거로 한 답변 + 근거 링크 |
| 오류 원인 분석 | 문의·오류 상황 → **5단 리포트** (① 문의·오류 요약 ② 예상 원인 ③ 관련 히스토리·근거 ④ 담당 팀·해결 방안 ⑤ 고객 답변 초안), 리포트 복사 |
| 자료 등록 | **GitHub 저장소 연결**(PR·이슈·커밋 가져오기), 문서 직접 등록, 텍스트 파일 불러오기 |

## 동작 흐름과 역할 나누기

```
① GitHub 저장소 연결 또는 문서 직접 등록
② 기록 정리 + 민감정보 마스킹 (코드)
③ 질문하면 관련 기록 찾기 (코드: 지금은 키워드 검색, 이후 임베딩)
④ 찾은 기록만 AI에게 넘겨 답변 생성 (AI)
⑤ 답에 붙은 근거 id가 실제로 넘긴 기록인지 검증, 아니면 버림 (코드)
⑥ 근거 원문(GitHub 링크)을 열어 직접 확인 (사람)
```

| 단계 | 누가 | 이유 |
|---|---|---|
| 기록 가져오기·정리·마스킹 | 코드 | 정해진 일이라 매번 같은 결과가 나와야 함 |
| 관련 기록 찾기 | 코드 → AI(임베딩 예정) | 지금은 키워드, 뜻으로 찾는 건 2주 차 |
| 답변·원인 후보 정리 | AI | 여러 기록을 읽고 흐름을 정리해야 함 |
| 근거 검증, 링크 붙이기 | 코드 | AI가 없는 근거나 링크를 만들지 못하게 |
| 맞는지 확인 | 사람 | AI가 틀린 기록을 근거로 댈 수 있음 |

**AI 규칙 (`lib/prompt.ts`)**
- 넘겨준 기록 안의 내용만 쓴다. 기록에 없는 원인·수치·담당자를 지어내지 않는다.
- 모든 원인·이유에 근거 기록 id를 붙인다. 링크는 쓰지 않는다(코드가 붙인다).
- 근거가 부족하면 답할 수 없다고 하고, 무엇이 부족한지 적는다.
- 결과는 정해진 JSON 형식으로만 낸다.

**OpenAI 키가 없을 때:** 가짜 답을 만들지 않고, "관련 기록"만 보여 줍니다.

## 시작하기 (Windows PowerShell)

```
git clone https://github.com/Baek0605/maclock.git
cd maclock
npm install
copy .env.example .env.local
# .env.local에 키를 채운다 (없어도 화면과 히스토리 검색은 동작)
npm run dev
```
브라우저에서 http://localhost:3000 을 엽니다.

> 프로젝트는 OneDrive 밖(예: `C:\dev`)에 두세요. `node_modules` 동기화 때문에 느려지거나 파일이 잠길 수 있습니다.

**써 보기**
1. 자료 등록 → GitHub 저장소 주소 입력 → 가져오기
2. AI 지식 검색에서 "이 기능 왜 바꿨어?", "이 에러 예전에 어떻게 고쳤어?"처럼 질문
3. 답의 근거 → "GitHub ↗"로 원문 확인

## 시험하는 두 가지 방법

**1. 가상으로 (크레딧 사용 안 함)**
- `.env.local`에 `MOCK_AI=1`을 넣고 서버를 다시 켠다. 화면 위쪽에 "가상 AI 모드"가 뜬다.
- 자료 등록 → **가상 저장소 불러오기 (테스트용)**: 개인 프로젝트 `error-lab`의 버그 5개를 이슈·PR·커밋으로 만든 예시 14건을 불러온다. 토큰·네트워크 없이 동작한다.
- AI 답은 진짜 분석이 아니라, 검색된 기록으로 답의 **형식**만 보여 준다. 화면 흐름, 근거 연결, 검색이 맞는 기록을 찾는지 확인할 때 쓴다.

**2. 실제 AI로 (크레딧 사용)**
- `.env.local`에서 `MOCK_AI`를 지우거나 `0`으로 바꾸고, `OPENAI_API_KEY`를 넣은 뒤 서버를 다시 켠다. 화면 위쪽에 "AI 연결됨"이 뜬다.
- AI 지식 검색 · 오류 원인 분석을 실행할 때만 크레딧이 나간다 (1번에 1센트 미만). 화면 열기, 히스토리 검색, 자료 등록, GitHub 가져오기는 크레딧이 들지 않는다.

**가상 저장소 질문 예시 (정답)**
| 질문 | 정답 기록 |
|---|---|
| 결제할 때 KeyError 났던 거 어떻게 고쳤어? | ISSUE-9, PR-10 |
| 주문할 때 수량 없으면 에러 나던 거 | ISSUE-3, PR-4 |
| 카테고리 평균 가격 0으로 나누기 에러 원인 | ISSUE-5, PR-6 |
| 일일 리포트 DB 연결 실패 | ISSUE-7, PR-8 |
| 프로필 조회 NoneType 에러 어떻게 고쳤지 | ISSUE-1, PR-2 |

## 키 관리 규칙 (중요)

- 키는 `.env.local`에만 둔다. `.gitignore`가 `.env*`를 막고 있으니 **이 설정을 지우지 않는다.** (`.env.example`만 예외로 올라감)
- 커밋 전에 `git status`로 `.env.local`이 목록에 없는지 확인한다.
- 키를 채팅방, 이슈, PR 설명에 붙여넣지 않는다.
- 배포할 때는 Vercel 환경 변수에만 등록한다.
- OpenAI는 서버 쪽 API Route(`app/api/...`)에서만 부른다. 화면 코드에서 직접 부르지 않는다.
- 예산: 운영진 지원 OpenAI 크레딧 $40. 질문 1번에 1센트 미만. 같은 사용자는 1분에 질문 10번, 가져오기 5번까지.

## 알아 둘 점

- **예시 기록(DOC·CS·CHG)은 가상 데이터**입니다. "친구 16,000명 / 15,000건 상한" 사례는 링커슈 인터뷰 구술을 재구성한 것이라, 멘토님 확인 전까지 발표에서는 "가상 사례"로 소개합니다.
- 가져온 기록과 직접 등록한 문서는 **지금 쓰는 브라우저에만 저장**됩니다. 여러 사람이 같은 자료를 보려면 Supabase 저장(선택 ④)이 필요합니다.
- 저장소 하나에서 PR·이슈·커밋을 각각 최근 150개까지 가져옵니다. 본문은 2,000자까지만 씁니다.

## 팀 작업 규칙

- `main`에 바로 올리지 않고 브랜치를 만든다. 예: `feature/embedding`
- 작업이 끝나면 PR을 올리고, 다른 팀원이 한 번 보고 합친다.
- **커밋과 PR 설명에 "무엇을 / 왜 바꿨는지"를 쓴다.** MacLock이 바로 그걸 찾아 주는 서비스라, 우리 저장소가 좋은 테스트 데이터가 된다.

자세한 단계와 일정은 [`docs/개발계획.md`](docs/개발계획.md)를 보세요.
